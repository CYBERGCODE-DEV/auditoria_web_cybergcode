CYBERGCODE WEB AUDIT INTELLIGENCE — DEPLOY V0.17.0 · MYSQL/MARIADB + POSTGRES

1. Subir el contenido del ZIP a la raíz del repositorio.
2. Confirmar package.json, vercel.json, api/, lib/, migrations/ y public/ en la raíz.
   El deployment debe generar 11 Functions; no restaurar los seis endpoints api/platform-* antiguos ni api/queues/.
3. Vercel instalará mysql2 3.24.3, @neondatabase/serverless y el resto de dependencias.
4. Confirmar ENGINE 0.17.0 y CG-STABLE-6.
5. Elegir proveedor SQL.

SEGURIDAD OBLIGATORIA EN PRODUCCIÓN
- Configurar CYBERGCODE_AUDIT_KEY con una clave larga y aleatoria.
- Configurar CYBERGCODE_REPORT_SECRET con otro secreto largo para autorizar PDFs.
- Mantener CYBERGCODE_ALLOW_ANONYMOUS_AUDITS=0.
- Mantener CYBERGCODE_ALLOW_ANONYMOUS_PERSISTENCE=0.
- Con base SQL, cuotas y locks de jobs usan tablas compartidas y operaciones atómicas; sin base se usa fallback por instancia y debe mantenerse Vercel Firewall.

MYSQL / MARIADB (recomendado si ya trabajas con ese ecosistema)
6. Crear una base vacía, por ejemplo: cybergcode_auditoria.
7. En Vercel > Settings > Environment Variables configurar:
   DB_PROVIDER=mysql
   DATABASE_URL=mysql://usuario:password@host:3306/cybergcode_auditoria
   CYBERGCODE_PLATFORM_KEY=<clave larga aleatoria>
8. Para MariaDB también puedes usar:
   DB_PROVIDER=mariadb
   DATABASE_URL=mariadb://usuario:password@host:3306/cybergcode_auditoria
9. Si el servidor exige TLS: DB_SSL=1.
10. Si prefieres crear las tablas manualmente, ejecutar migrations/mysql/001_platform.sql.

TIDB CLOUD
11. Usar DB_PROVIDER=tidb y la URL MySQL del cluster; el driver activa TLS para hosts tidbcloud.com.

POSTGRES / NEON (sigue soportado)
12. DB_PROVIDER=postgres o neon.
13. DATABASE_URL=postgresql://...
14. Migración manual opcional: migrations/postgres/001_platform.sql.

17. Confirmar Proveedor/Dialecto/Servidor = conectado.
18. Ejecutar una auditoría de 12–25 páginas.
19. Ejecutar otra del mismo dominio y revisar Historial.
20. Abrir Comparar y verificar Antes vs Después.
