CYBERGCODE WEB AUDIT INTELLIGENCE — DEPLOY V0.21.1 · VALIDACIÓN SEGURA DE SUPABASE SQL

1. Subir el contenido del ZIP a la raíz del repositorio.
2. Confirmar package.json, vercel.json, api/, lib/, migrations/ y public/ en la raíz.
   El deployment debe generar 12 Functions; la demo comparte la Function de identidad para respetar el límite Hobby.
3. Vercel instalará mysql2, postgres.js y el resto de dependencias.
4. Confirmar ENGINE 0.21.1 y CG-STABLE-6.
5. Elegir proveedor SQL.

SEGURIDAD OBLIGATORIA EN PRODUCCIÓN
- Crear un proyecto Supabase y desactivar el registro público.
- Configurar SUPABASE_URL, SUPABASE_ANON_KEY y SUPABASE_SERVICE_ROLE_KEY únicamente en Vercel.
- Crear el primer usuario en Supabase Authentication y colocar su correo exacto en CYBERGCODE_ADMIN_EMAILS.
- Configurar la URL del sitio y https://DOMINIO/?activate=1 como Redirect URL autorizada en Supabase.
- Configurar CYBERGCODE_REPORT_SECRET con otro secreto largo para autorizar PDFs.
- Mantener CYBERGCODE_ALLOW_ANONYMOUS_AUDITS=0.
- Mantener CYBERGCODE_ALLOW_ANONYMOUS_PERSISTENCE=0.
- CYBERGCODE_AUDIT_KEY y CYBERGCODE_PLATFORM_KEY solo son fallback legado cuando Supabase no está configurado.
- Con base SQL, cuotas y locks de jobs usan tablas compartidas y operaciones atómicas; sin base se usa fallback por instancia y debe mantenerse Vercel Firewall.

MYSQL / MARIADB (recomendado si ya trabajas con ese ecosistema)
6. Crear una base vacía, por ejemplo: cybergcode_auditoria.
7. En Vercel > Settings > Environment Variables configurar:
   DB_PROVIDER=mysql
   DATABASE_URL=mysql://usuario:password@host:3306/cybergcode_auditoria
8. Para MariaDB también puedes usar:
   DB_PROVIDER=mariadb
   DATABASE_URL=mariadb://usuario:password@host:3306/cybergcode_auditoria
9. Si el servidor exige TLS: DB_SSL=1.
10. Instalación nueva: ejecutar 001_platform.sql, 002_multiuser.sql y 003_admin_events.sql. Instalación existente: ejecutar 002 y después 003.

TIDB CLOUD
11. Usar DB_PROVIDER=tidb y la URL MySQL del cluster; el driver activa TLS para hosts tidbcloud.com.

POSTGRES / NEON (sigue soportado)
12. DB_PROVIDER=postgres o neon.
13. DATABASE_URL=postgresql://...
14. Instalación nueva: ejecutar 001_platform.sql, 002_multiuser.sql y 003_admin_events.sql. Instalación existente: ejecutar 002 y después 003.
